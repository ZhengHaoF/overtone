真实折射对照稿

上一版的问题不是「不够半透明」，而是根本没有折光：backdrop blur + 渐变底色 + 一圈描边，本质仍是磨砂塑料。 这一版按苹果 iOS 26 的 Liquid Glass 重建：由圆角矩形 SDF 生成位移场，让背景在边缘被真实地折弯、局部翻转与放大； 再叠三通道色散、随时间/指针移动的镜面高光、以及融合时的表面张力。

圆角矩形 SDF 的法线：灰心 + 四向彩色轮环 = 360° 边缘折射；强度随距离衰减。
为什么右边在「动」：位移量不是固定偏移，而是随距离边缘的 SDF 值变化。背景内容经过时，边缘附近的采样坐标被推向玻璃外侧， 超出元素边界的部分被浏览器镜像回来，于是形成一条窄窄的倒像带；再往内是轻微放大，中央恢复 1:1。这就是透镜感，而不是模糊感。

03 / MERGE

融合不是淡入淡出

两个胶囊在距离小于阈值时，轮廓先出现「颈部」，再整体并成一个形。苹果官方文档的原话是 “the Liquid Glass effects behind views blend together and merge the shapes”（`GlassEffectContainer(spacing:)`）——是几何并集，而不是交叉淡化。

04 / COST

性能：哪些滤镜最贵

真实折射的代价是「每帧多一次离屏采样」。同屏玻璃层越多、面积越大，越接近 GPU 填充率瓶颈。下面的 FPS 是本页实时测量值，可开关「真实折射」直接对照。

—FPS · 实时
层 / 操作昂贵程度说明
3× feDisplacementMap极高每通道一次全区域重采样；色散开启时 ×3，仅给大面板
backdrop-filter blur高σ 每增加 1，采样核变大；v2 刻意降到 σ2.5，靠折射而非模糊
saturate / contrast中逐像素矩阵，面积正比开销
1px 渐变描边 + 柔光低静态绘制，只在你滚动时随合成器重绘
mask-image 每帧替换中融合演示逐帧换 PNG mask；真实工程应改为 shader
本页 0 个折射元素；其中 0 个走三通道色散，其余单通道。桌面 Chrome 通常在 50–60fps；集显 / 4K 屏可能掉到 30fps 以下。

怎么读这组数字

  • 位移峰值：边缘采样坐标向外推的最大距离（CSS px）。不是模糊半径。
  • 带宽：从轮廓往里，折射衰减到 0 的距离。约为元件短边的 15–25%，本稿按 tier 固定 8 / 14 / 22。
  • 色散：R/B 通道相对 G 各多/少 4.5% 的位移量，形成 1px 级彩边，不是整块染色。
  • 饱和：saturate 1.62；v1 为 1.45。差别在「玻璃是否把背景提鲜」，而不是透明度。
  • 高光：顶边 1px 亮线 + 左上 12px 柔光 + 指针 ±10px 的镜面移动；光源假设统一为左上。
同屏多层时，优先砍「三通道色散」和「大面积的 thick 面板」，而不是砍高光——高光便宜，且是玻璃感的主要来源。
